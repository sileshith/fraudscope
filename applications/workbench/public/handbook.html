FRAUDSCOPE / APPLICATION HANDBOOK / VERSION 2.0

A working fraud review workflow

This is a private application using synthetic data. The trained models, database and review actions run on the server. It does not process or block payments.

Your first five minutes

  1. Sign in with the ChatGPT account that owns the application.
  2. From Overview, select Replay demo feed. The app scores and saves 24 constructed transactions per click.
  3. Open Review queue and select a transaction. Inspect its active score, observed evidence, and earlier account/device neighbors.
  4. Select Compare all four neural models to compute the MLP, relational mean, temporal attention and risk-gated attention scores for that case.
  5. Choose an analyst judgment, explain your reasoning, and save it. The revision and audit trail are persisted.
  6. Open Audit trail and select Verify integrity. Export a CSV when you want to inspect records elsewhere.

How to read a score

The active logistic model uses its original held-out calibration and fixed validation threshold. A review priority is not a finding of fraud. The risk-gated temporal GNN is deployed in shadow, and does not change the queue decision. The other neural candidates can be run on demand.

The application starts with empty history. Earlier submitted transactions create account and device neighborhoods. A new account or device can therefore have no graph neighbors. Equal-time events and future events cannot enter a transaction's features.

Evidence and limits

The JavaScript inference was compared with Python on 80 independent model fixtures. A second 48-event test checks the full persistent scoring workflow. Original three-seed results are synthetic research evidence, not metrics measured on your constructed replay stream.

Review judgments are not verified chargeback labels. No retraining or automatic model promotion occurs. A fixed threshold does not guarantee a 5% review rate on changing data. The capacity explorer does not alter the deployed policy.

The workspace allows 240 replay events and up to 12,000 committed actions. The source includes the Python research project, application tests, model-export script, database migrations and deployment guidance. The older research PDF describes version 1.1 before the new application was deployed.

Before adapting it to real data

Run an authorized IEEE-CIS benchmark or your own approved dataset. Validate scoring-time feature availability, identity relations, label delays and business costs. Complete real-world load tests, access review, retention, backups, recovery drills, external audit anchoring, model-risk review and operational ownership before making financial decisions.
